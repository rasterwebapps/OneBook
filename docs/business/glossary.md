## A–C

### Adapter Pattern
A software design pattern used in the OneBook ingestion pipeline. Each external data source (HL7, ISO20022, DMS, Webhook) implements the `ExternalAppAdapter` interface. New adapters can be added without changing core ingestion logic. See `docs/business/TRD.md#tr-006`.

### AES-256-GCM
**Advanced Encryption Standard** with 256-bit keys in **Galois/Counter Mode**. The encryption algorithm used in OneBook for field-level encryption. GCM provides both confidentiality (encryption) and integrity (authentication tag). A unique 12-byte IV (Initialization Vector) is generated for every encryption operation. See `FieldEncryptionService.java`.

### Anomaly Detection
An AI-powered feature in OneBook (M8) that identifies transactions deviating statistically from historical patterns. Each transaction receives an anomaly score (0.0–1.0). Scores above the configured threshold trigger alerts to the Finance Manager. See `AnomalyDetectionService.java`.

### Audit Trail
A chronological, tamper-evident record of all state-changing operations in OneBook. Each entry contains: entity type, entity ID, action, actor, timestamp, change payload, and a SHA-256 hash chained to the previous entry. Any modification to an existing entry is detectable by hash chain verification. See `AuditLogService.java`.

### Balance Sheet
A financial statement showing an entity's assets, liabilities, and equity at a specific point in time. Governed by the accounting equation: **Assets = Liabilities + Equity**. Generated by `BalanceSheetService.java` in OneBook.

### Bank Reconciliation
The process of matching a company's internal bank ledger with the bank statement to identify discrepancies, uncleared cheques, and bank charges. OneBook supports CSV/OFX/MT940 import and auto-matching. See `BankReconciliationService.java`.

### Blind Index
A cryptographic technique used in OneBook to enable equality search on encrypted fields. Computed as `HMAC-SHA256(blindIndexKey, normalize(plaintext))`. Stored alongside the ciphertext. Supports `WHERE blind_index = ?` queries without decrypting database rows. See `BlindIndexService.java`.

### Branch
A business unit within a company that has its own books but rolls up to the parent company for consolidation. In OneBook's multi-entity hierarchy: Enterprise → Company → Branch → Cost Center.

## D–G

### Cache-Aside
A caching pattern where the application checks the cache first; on a miss, it queries the database, stores the result in cache, and returns it. In OneBook: Redis is the cache layer, PostgreSQL is the authoritative store. TTL defaults to 30 minutes. See `WarmCacheService.java`.

### Cash Flow Statement
A financial statement showing cash inflows and outflows categorized into Operating, Investing, and Financing activities. Generated by `CashFlowService.java` in OneBook.

### Chart of Accounts
A structured list of all ledger accounts for a business, organized by type (Assets, Liabilities, Income, Expenses, Equity). In OneBook, accounts form a hierarchical tree stored in `ledger_accounts` table with RLS enforcement.

### Cost Center
An organizational unit (department, project, location) used to track financial performance at a granular level without separate books. Journal entries can be allocated to cost centers. Reports can be filtered and grouped by cost center.

### Credit
A bookkeeping entry that increases Liability, Income, or Equity accounts, and decreases Asset or Expense accounts. In double-entry bookkeeping, every credit must have a corresponding debit.

### Debit
A bookkeeping entry that increases Asset or Expense accounts, and decreases Liability, Income, or Equity accounts. In double-entry bookkeeping, every debit must have a corresponding credit.

### Depreciation
The systematic allocation of a fixed asset's cost over its useful life. OneBook supports two methods:
- **SLM (Straight-Line Method):** `(Cost - Residual Value) / Useful Life`
- **WDV (Written Down Value):** `Opening Book Value × Depreciation Rate`

### Double-Entry Bookkeeping
The foundational accounting principle that every financial transaction must be recorded with at least one debit and one credit of equal value. OneBook enforces this at three layers: service, database trigger, and exception surfacing.

### DTO (Data Transfer Object)
A Java record used to transfer data between API layers. In OneBook, JPA entities are never exposed in REST responses — all responses use DTO records in the module's `dto/` package.

### e-Invoice (IRN)
**Invoice Reference Number** — a unique identifier assigned by the GST Network (GSTN) for B2B invoices above the prescribed threshold (₹5 lakh). OneBook generates e-Invoices via `ComplianceService.java` and stores the IRN and QR code with the voucher.

### e-Way Bill
An electronic document required under GST for movement of goods worth ₹50,000 or more. Generated in OneBook via `ComplianceService.java`.

### Encryption Key
A cryptographic secret used for AES-256-GCM encryption. In OneBook, keys are loaded from environment variables (`ONEBOOK_ENCRYPTION_KEY`) via `KeyManagementService.java`. Never stored in source code or application.yml.

### Fixed Asset Register (FAR)
A schedule of all capital assets owned by an entity, including cost, accumulated depreciation, book value, and disposal details. OneBook maintains the FAR in `FixedAssetService.java`.

### Flyway
A database migration tool used in OneBook to version-control PostgreSQL schema changes. Migrations are numbered V1–V10 in `backend/src/main/resources/db/migration/`.

### Forecasting (AI)
OneBook's AI-driven cash flow forecasting feature (M8). Uses historical journal data to project cash inflows and outflows for 30/60/90/180 day horizons with confidence intervals. See `ForecastingService.java`.

### GST (Goods and Services Tax)
India's unified indirect tax system replacing VAT, Service Tax, and Excise Duty. OneBook supports GSTR-1 generation, e-Invoice, e-Way Bill, and GST reconciliation.

## H–J

### Hash Chain
A sequence of cryptographic hashes where each hash includes the previous hash as input. Used in OneBook's audit trail. Any modification to a historical record breaks the chain and is detectable. See `AuditLogService.java`.

### HMAC-SHA256
**Hash-based Message Authentication Code** using SHA-256. Used in OneBook to compute blind indexes. `HMAC(key=blindIndexKey, message=normalizedValue)`. Provides a deterministic, one-way index for encrypted field search.

### HL7
**Health Level 7** — a set of international standards for healthcare data exchange. OneBook's M6 ingestion pipeline includes an HL7 adapter that translates hospital billing events into journal entries.

### Intercompany Elimination
The process of removing intercompany transactions (sales, loans, transfers between related entities) when preparing consolidated financial statements, to avoid double-counting.

### ISO20022
An international standard for electronic financial messaging used by banks and payment systems. OneBook's ISO20022 adapter (M6) processes `camt` (account statements) and `pain` (payment initiation) messages.

### IV (Initialization Vector)
A 12-byte random value used in AES-GCM encryption. Must be unique for every encryption operation. Stored as the first 12 bytes of the ciphertext wire format in OneBook. Reusing IVs with the same key breaks GCM security.

### Journal Entry
A single debit or credit line within a journal transaction (voucher). Each journal transaction has two or more journal entries. OneBook stores entries in `journal_entries` table.

### Journal Transaction
A financial transaction record (voucher) containing a header (type, date, narration) and two or more balanced journal entries. Corresponds to a row in `journal_transactions` table.

### JWT (JSON Web Token)
A compact, URL-safe token format used in OneBook for API authentication. Contains tenant ID, user ID, and roles. Validated by Spring Security on every API request.

## K–M

### Key Management Service
`KeyManagementService.java` — loads encryption keys from environment variables, manages key versioning for rotation, and provides the current key to `FieldEncryptionService`.

### Key Rotation
The process of replacing the encryption key while keeping encrypted data accessible. OneBook's wire format includes a version byte in each ciphertext, allowing multiple key versions to coexist during rotation.

### Ledger Account
A named account in the chart of accounts. Examples: "Cash in Hand" (Asset), "Sales Revenue" (Income), "TDS Payable" (Liability). Stored in `ledger_accounts` table.

### Maker-Checker-Approver
A three-tier separation-of-duties workflow:
- **Maker:** Creates a voucher (DRAFT status)
- **Checker:** Reviews and approves (CHECKED status)
- **Approver:** Final approval for high-value transactions (APPROVED → POSTED)
Ensures no single person can create and approve their own financial transactions.

### Mark-to-Market (MTM)
The accounting practice of valuing assets at current market prices rather than historical cost. OneBook's M8 AI module includes `MarkToMarketService.java` for portfolio and investment valuation.

### Multi-Tenancy
The ability of a single software system to serve multiple independent customers (tenants) with complete data isolation. OneBook uses single-database multi-tenancy enforced by PostgreSQL Row-Level Security.

## N–R

### Narration
A free-text description attached to a journal voucher explaining the nature of the transaction. In OneBook, narrations are encrypted with AES-256-GCM before storage.

### Period Close
The process of finalizing accounting records for a period (month, quarter, or year), locking journal entries, and generating financial statements. After period close, entries cannot be modified.

### P&L (Profit and Loss)
Also called the **Income Statement** — a financial report showing revenues, expenses, and net profit/loss for a period. Generated by `ProfitAndLossService.java` in OneBook.

### RLS (Row-Level Security)
A PostgreSQL feature that enforces data access policies at the database row level. In OneBook, every tenant-scoped table has an RLS policy: `USING (tenant_id = current_setting('app.current_tenant_id')::uuid)`. Provides infrastructure-level tenant isolation.

### Reconciliation
See **Bank Reconciliation**.

### Redis
An in-memory data store used in OneBook as a warm cache. Stores decrypted account data, report results, and session information to eliminate repeated AES-GCM decryption overhead. Key TTL: 30 minutes default.

## S–V

### Signals (Angular)
Angular 19's reactive primitive for state management. `signal()` creates mutable state; `computed()` derives state; `effect()` runs side-effects. Used in OneBook for all component-local state without requiring RxJS.

### TCS (Tax Collected at Source)
A tax mechanism under Indian Income Tax Act where the seller collects tax from the buyer at the point of sale for specified goods/transactions. Auto-computed by `TdsTcsService.java` in OneBook.

### TDS (Tax Deducted at Source)
A tax mechanism under Indian Income Tax Act where the payer deducts tax from payment before remitting to the payee. Auto-computed at source by `TdsTcsService.java`. Section codes include 194A (interest), 194C (contractors), 194H (commission), 194I (rent), 194J (professional fees).

### Tenant
An independent organization using OneBook as their accounting OS. Each tenant has their own chart of accounts, journal entries, users, and configuration. Data isolation is enforced via RLS.

### TenantConfig
The configuration entity per tenant (locale, currency, fiscal year start, encryption key reference). Stored in `tenant_config` table with RLS.

### Trial Balance
A report listing all ledger accounts with their debit and credit balances as of a date, used to verify that total debits equal total credits. Generated by `TrialBalanceService.java` in OneBook.

### Transloco (@jsverse/transloco)
The i18n library used in the OneBook Angular frontend. Supports multiple languages, lazy loading of translation files, and runtime language switching.

### Voucher
See **Journal Transaction**. The term "voucher" is used in Indian accounting (Tally-style) to refer to a source document for a journal entry. Types: Payment, Receipt, Journal, Contra, Sales, Purchase, Debit Note, Credit Note.

### Virtual Threads (Project Loom)
A Java 21+ feature providing lightweight, heap-allocated threads managed by the JVM. OneBook enables virtual threads via `spring.threads.virtual.enabled=true`. Supports 10,000+ concurrent connections without OS thread pool exhaustion.

## W–Z

### Warm Cache
OneBook's strategy of pre-populating Redis with frequently accessed data at user login time. Eliminates AES-GCM decryption latency for the first request — providing Tally-speed responsiveness. See `WarmCacheService.java`.

### WDV (Written Down Value)
A depreciation method where the depreciation is calculated as a fixed percentage of the current book value (declining balance). Book value = Cost − Accumulated Depreciation.

### Zero-Knowledge
A security design principle where the database (and database administrators) cannot read sensitive data values, because all sensitive fields are encrypted in the application layer before being stored. OneBook achieves this via AES-256-GCM field encryption with keys stored only in environment variables.

### Zero-Trust
A security architecture principle of "never trust, always verify." In OneBook:
- Every API request must present a valid JWT
- Tenant context is validated before every database operation
- RLS enforces isolation even if application-level checks fail
- Audit trail detects tampering even after data is written
